# PELCLO CONTENT HQ — редакционная система
Версия: 0.1 (черновик для обсуждения) · 11.11.2026

> Главный документ правил для личного блога о мужском стиле и приложения Pelclo. Все изменения правил фиксируются здесь. Черновые положения требуют утверждения владельцем.

## 1. Зачем мы делаем контент
- Помогать мужчинам разбираться в стиле, давать конкретные применимые советы.
- Формировать доверие к автору через собственный вкус, опыт, понятные объяснения.
- Нативно знакомить аудиторию с Pelclo, не превращая блог в рекламу.
- Разделять полезность, эстетику, вовлечение и продвижение.

## 2. Каналы и объём (целевые ориентиры, корректируются)
- Instagram: 7 информативных Reels в неделю и 3–5 лёгких Reels; 2–3 карусели в неделю; Stories ежедневно.
- Telegram @dimapels: 14–21 публикация в неделю, в том числе короткие форматы. Окна: 10:00, 18:00, опционально 22:00 по Москве.
- Около 25% Reels могут нативно затрагивать Pelclo; без навязчивого повторения.
- План следующей недели готовится по пятницам; выходные — на проверку и корректировки.

## 3. Редакционные принципы
- Тон: живой, конкретный, уверенный, без назидательности и канцелярита.
- Не использовать искусственные маркетинговые клише, пустые обещания и безосновательные категоричные суждения.
- По возможности показывать конкретные вещи, сочетания, ошибки, альтернативы и практическую пользу.
- Не использовать шаблонную конструкцию «а не» и механические перечисления после двоеточий; избегать перегруженности двоеточиями.
- Не копировать чужие тексты и изображения без прав; проверять факты, цены, наличие, названия брендов.
- Учитывать реальную сезонность, погоду и бюджет аудитории, если это существенно для темы.
- Разделять авторское мнение и проверяемые факты.
- Избегать повторения одной темы или визуала в соседних публикациях без редакционной причины.

## 4. Форматы
### Reels
- Хук в первые секунды, одна понятная мысль, наглядный пример, естественный финал.
- Сценарий пишется для живой речи, без перегруженных формулировок.
- Съёмочные подсказки отдельно от произносимого текста.
- Pelclo упоминать только там, где приложение решает показанную проблему.

### Карусели Instagram
- Один основной тезис на карусель, логичная последовательность слайдов.
- Короткие читаемые блоки текста, выразительная обложка, аккуратная типографика.
- Макеты создаются в Figma, итоговый экспорт — отдельные изображения слайдов.

### Stories
- Ежедневный контакт с аудиторией: наблюдения, процесс, опросы, вопросы, подборки.
- Интерактив должен быть связан с темой, а не добавлен формально.
- В Figma готовятся только те Stories, которым нужен дизайн; живые видео/фото могут оставаться задачами на съёмку.

### Telegram
- Не дублировать Instagram дословно; давать дополнительный контекст, личные наблюдения, полезные подборки.
- Текст должен быть самостоятельным, понятным без перехода в Instagram.
- Проверять ссылки и вложения. Дата/время в часовом поясе Europe/Moscow.

## 5. Визуальная система (проект правил, требует утверждения)
- Эстетика: минимализм, редакционная fashion-подача, аккуратные композиции, воздух.
- Единые шрифты, палитра, сетка, отступы, формат изображений и правила обложек должны быть закреплены после утверждения эталонных макетов Figma.
- Нельзя менять утверждённую визуальную систему без отдельного решения.
- Не использовать случайные изображения, не относящиеся к материалу; вести учёт уже использованных.
- Ссылки на эталонные Figma-файлы и параметры экспорта фиксируются здесь после согласования.

## 6. Объект контента и версии
Каждый материал имеет: ID, канал, формат, рубрику, тему, цель, текст, ссылки на Figma и медиа, ответственного, версию, статус, замечания, дату/время, факт публикации и результат.
Изменение текста/изображений/времени после одобрения сбрасывает одобрение (или требует повторного подтверждения конкретной версии).

## 7. Согласование и безопасность
Статусы: идея → в работе → на проверке → на доработке/одобрено → запланировано → опубликовано (для Instagram: готово к скачиванию).
- Только явное подтверждение владельца утверждает конкретную версию.
- Никаких автоматических публикаций без подтверждения.
- Telegram: только одобренные посты с наступившим временем уходят в очередь; бот в отдельном приватном репозитории pelclo_tg публикует через GitHub Actions.
- Instagram: одобрение запускает экспорт финальных слайдов/Stories в Google Drive; Instagram публикуется вручную.
- Ошибки экспорта/публикации видны в штабе, не маскируются под успех.
- Запретить дубли по ID и повторные отправки; учитывать риск повторов при сбоях после отправки.

## 9. Архитектура
- Сайт: отдельный React frontend на GitHub Pages.
- GitHub Pages публичен; он не обеспечивает приватность данных.
- На этапе прототипа данные локальны (localStorage), согласование не связано с реальной публикацией.
- Следующий этап: Supabase Auth + RLS, защищённые таблицы и серверный механизм доставки команд. Никогда не размещать Telegram token, GitHub PAT или service_role key в клиентском коде.
- Источник истины после интеграции: защищённая база данных; GitHub-очередь Telegram — только транспорт/исполнение.
- Google Drive и Figma интегрируются через разрешённые подключения; нельзя считать экспорт реализованным до проверки.

## 10. Еженедельный процесс
1. Пятница: идеи и полный план на следующую неделю с темами, целями, датами и каналами.
2. Выходные: комментарии и согласование.
3. После согласования: подготовка/финализация текстов и дизайнов, отдельная проверка финальной версии.
4. Telegram: автоматическая публикация по утверждённому времени.
5. Instagram: экспорт в Drive, ручное скачивание и публикация.
6. В конце недели: разбор результатов и корректировка правил.

## 13. Позиционирование автора (согласовано 11.11.2026)
- Главная идентичность: fashion-блогер с собственным узнаваемым стилем и вкусом, при этом полезный аудитории.
- Показывать личный выбор, реальные образы, покупки, примерки, наблюдения, эстетику и объяснение решений.
- Не сводить блог к обезличенным инструкциям и универсальным «топ-5».
- Практическая польза усиливает авторский взгляд, не подменяет его.

## 14. Контентные цепочки и переходы между площадками (согласовано 11.11.2026)
- Роли площадок: Instagram Reels — привлечение новой аудитории; Instagram Stories — удержание, контакт и интерактив; Telegram — более глубокая связь с автором, дополнительные материалы и личный контекст.
- По возможности связывать публикации одного дня общей темой, но не требовать этого каждый день.
- Основные варианты: Reels → Stories → Telegram; Reels → Telegram; Reels → Stories; самостоятельная публикация без переходов.
- Для старта ориентир — 2–3 полноценные цепочки в неделю, остальное самостоятельный контент или короткие связи; частоту корректировать по результатам.
- Пример «ботинки»: Reels с личным выбором и объяснением → Stories с конкретными моделями/опросом → Telegram с расширенной подборкой, ссылками и авторскими комментариями.
- Каждая единица контента должна быть полезной самостоятельно. Не обрывать объяснение искусственно ради перехода.
- Призыв к переходу допустим только при реальной дополнительной ценности на следующей площадке; формулировать естественно и разнообразно.
- Telegram-пост должен быть опубликован или гарантированно подготовлен к моменту, когда Reels/Stories направляют в него аудиторию. При ручной публикации Instagram учитывать фактическое время выхода.
- Контентная цепочка — отдельная сущность с ID, общей темой, целью, связанными материалами, переходами и статусами каждого материала.
- В редакторе предусмотреть поле «Куда ведём аудиторию»: Stories / Telegram / Pelclo / без перехода. У каждого материала отдельные время, версия, статус и согласование.
- Не использовать навязчивые CTA в каждом ролике. Оценивать результат по сохранениям, досмотрам, переходам, подпискам и реакции аудитории, если данные доступны.
